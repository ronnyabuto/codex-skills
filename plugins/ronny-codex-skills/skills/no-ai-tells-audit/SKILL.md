# Codebase Readability Cleanup

This workflow edits the requested codebase scope. An audit-only request calls for findings, not edits. Ordinary file cleanup does not imply a repository-wide sweep.

Work in the authorized checkout. Inspect working-tree changes and avoid concurrent writes to the same files. Use an isolated worktree when concurrent work requires it; do not silently move away from a branch containing the user's task.

1. Inspect the scoped source and record concrete readability problems with locations and reasons. Exclude generated/vendor files, legal text and intentional documentation.
2. Remove redundant narration, obsolete scaffolding or naming mismatches only when inspection confirms the change improves readability. Keep comments explaining real constraints, documented contracts, workarounds and tracked TODOs.
3. Before changing logic or removing defensive checks, inspect callers/tests and relevant history to establish their purpose. If unknown, preserve the uncertain behavior or make only the scoped change supported by evidence.
4. Assess repeated code by semantics and maintenance cost. Do not unify policy merely because text looks similar, and do not impose a new architecture.
5. Make coherent batches and run affected checks after behavior changes. Use proportionate verification for comment-only batches; record what was tested.

Report categories and representative examples of actual changes, any findings deliberately left alone, and validation. Do not present heuristics as proof that code was generated by AI. User requirements and project conventions override these preferences. This skill is self-contained; no sibling skills or root orchestration file are required.
